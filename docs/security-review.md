# 공개본 보안과 검증 범위

공개본 준비일: 2026-10-09, 한국 시간.

## 공개본에서 분리한 정보

- 운영 주소와 production 배포 job 제거
- 실제 환경변수 없이 예시 템플릿만 포함
- 기존 Git 이력 대신 새 이력으로 시작
- 샘플 회원을 번호 이름·전화번호 없음·임의 생년월일로 변경
- 개발 계정 비밀번호는 로컬 전용으로 명시
- 실제 회원 사진·QR·CSV 미포함

## 코드의 보호 장치

서버 역할 검사·DB RLS·RPC 권한 검사, 승인 상태 재검사, 원래 차감권 복구·사유·감사 이력, 체크인 GET의 업무 변경 방지, 명시적 POST, 새 QR fragment 토큰과 검증된 SITE_URL, 유효 토큰별 1분 6회 DB 제한, CSV 수식 방어와 비공개 응답 캐시 방지를 유지합니다.

## 검증 범위

앱·DB 테스트 코드를 유지합니다. 검사 결과는 이 공개 저장소의 GitHub Actions에서 확인할 수 있습니다. 테스트 DB의 통과는 운영 환경의 보안 적용이나 모든 동시성 상황을 보장하지 않습니다.

## 별도 환경에 배포할 때

- Supabase signup을 차단합니다. 신규 Auth 계정은 기본 코치 프로필로 생성됩니다.
- 개발 계정·seed를 운영에 적용하지 않습니다.
- 전체 migration과 실제 RLS·RPC·Storage 정책을 확인합니다.
- 서비스 키와 Cloudflare API 토큰은 서버 Secrets로 관리합니다.
- QR 카드·signed URL·CSV·감사 로그에는 개인정보가 포함될 수 있습니다.
- 계정 활성 필드만 변경해서 접근을 폐기할 수 없습니다. Auth 계정·세션 폐기 절차를 정해야 합니다.
- 유효 토큰 한도와 별개로 무효 토큰·전체 트래픽 제한을 구성합니다.
- DB와 Storage 파일을 별도 백업하고 복구를 시험합니다.
- 다중 연결 동시성과 등록·조정·승인·취소의 잠금 순서를 검증합니다.

이 문서는 공개본의 범위와 알려진 한계이며 운영 환경에 직접 접근한 보안 인증 결과는 아닙니다.


## 공개본 의존성 점검 (2026-10-09)

호환 범위의 npm audit fix를 적용했습니다. 런타임 의존성 검사 npm audit --omit=dev는 0건입니다. 전체 검사에는 ESLint의 braces 전이 의존성 한 경로에서 High 5개 패키지 항목이 남습니다. 이는 별도 취약점 5개를 뜻하지 않습니다. 해당 braces 공지는 패치 버전이 없다고 안내합니다. 강제 수정은 eslint-config-next를 14대로 내리므로 적용하지 않았습니다. 개발·CI에서 신뢰하지 않는 중첩 glob 패턴을 처리하지 않고, 상위 도구의 호환 수정이 나오면 갱신합니다.
